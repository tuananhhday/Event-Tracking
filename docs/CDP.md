# CDP collector

Node.js 24 provides the WebSocket/fetch clients. The collector uses raw Chrome DevTools Protocol. It does not depend on an extension, Selenium, or Playwright.

When the app opens a test browser, it creates and activates a known top-level page using the browser connection. It navigates that exact target and main frame, rather than the first discovered page (which may be an Edge onboarding/sign-in dialog). Headful test windows request a maximized normal browser window; manually attached tabs are left under the user's control. `node scripts/browser-start-smoke.mjs` verifies that an existing startup page remains unchanged while the website loads in a different top-level page.

- Browser launch always uses a separate profile in `.profiles/`, a localhost debug address, and an explicit debug port. The normal user browser is never terminated. An existing debug port must be attached explicitly instead of silently reused by the launcher.
- Edge `RemoteDebuggingAllowed=0` in HKLM/HKCU policy is reported as an error; the tool does not bypass it.
- `Runtime.addBinding` and `Page.addScriptToEvaluateOnNewDocument` capture `dataLayer`/`InsiderQueue`. Existing default frame contexts are also instrumented. New same-renderer and out-of-process iframe contexts are handled. A 750 ms discovery poll attaches matching new tabs.
- Existing queue contents are historical evidence and do not belong to a newly started test step. Late/replacement arrays are hooked synchronously when their property permits it.
- Vendors replace `push` after the page creates the queue. On vinpearlota.com (checked 2026-11-01) the Insider SDK assigns `InsiderQueue.push = function(e){ … Array.prototype.push.call(this, e) }`, which never calls the push it replaced, and GTM assigns a `dataLayer.push` that does call it. The collector therefore installs `push` as a getter/setter: the setter keeps the vendor function and the getter returns it wrapped, so no push is lost between the vendor's assignment and the next poll. A shared depth guard prevents duplicate evidence when a vendor push calls an earlier wrapper. The 500 ms poll remains a fallback for queues whose `push` was redefined with `Object.defineProperty`.
- `Insider.eventManager.dispatch(name, data)` is hooked for tracking events such as `other_page_view`. The SDK also dispatches its own lifecycle signals there (`web-sdk:log`, `hit:userEvent:sent`, `predictive:loaded`…); names containing `:` are ignored.
- `push` arguments, its receiver and its return value are preserved. Payloads are snapshotted without mutation, after the original `push` returns (the timestamp is taken before the call), so fields the vendor adds to the pushed object, such as GTM's `gtm.uniqueEventId`, appear as they do in DevTools. `queue_index` is the element's position in the array, so the F12 view (`/api/pushes`) lists each `dataLayer`/`InsiderQueue` element once, in order; a batched Insider `custom_event` is one element. Stop removes injection registrations/bindings and restores properties where ownership can still be established.
- `stop({timeoutMs:3000})` disables capture immediately and performs frame cleanup in parallel under a single deadline capped at three seconds. It then disconnects even if frames, commands, or a callback never finish. `forceStop()` synchronously cancels discovery/startup and disconnects; generation guards prevent older connections from emitting into a restarted session. A deadline may leave unreachable page-side wrappers until navigation, while the disconnected collector no longer records their calls.
- `closeOwnedBrowser(handle,{timeoutMs:1500})` is separate from collector detach. It accepts only the original handle returned by this process's launcher, checks that its child is alive, and compares the browser WebSocket identity before `Browser.close`. Attached browsers, copied handles and reused debug ports are never followed. Endpoint/command shutdown shares one deadline; this helper does not terminate processes.
- Network captures configured hostname/path patterns only. The default Insider patterns are the event endpoints `hit.api.useinsider.com/hit` (page views) and `unification.useinsider.com/api/event/` (custom and cart events); Insider's segment, user-data, log and info hosts are not events. CORS OPTIONS preflight is excluded from event counts. Request payloads use `request.postData` or `Network.getRequestPostData`, then the shared decoder. Request, response, and failure records have separate `network.phase` values and keep the original request timestamp. Only request phase counts as an event.
- A push is not a fired event. `src/core/delivery.mjs` links each business push to the vendor request that sent it (one request per push): the GA4 `/g/collect` hit with the same event name within 30 s (GA4 batches hits), Insider's `pageView` hit after the `init` that follows page data, `item_added_to_cart` / `item_removed_from_cart` for cart pushes and the event name for custom events. A push without a request after 10 s is `not_sent`. The event list, specification coverage, firing checks and reports all use these links; GA4 events are shown and checked with the parameters Google received, and fields the website pushed but the hit lacks are reported as not forwarded by the GTM tag.
- Insider hits are named and shown as Insider records them (`src/core/insider-hit.mjs`). A `pageView` hit is named by its `page_type` (`main` → `homepage_view`, `category` → `listing_page_view`, `productDetail` → `product_detail_page_view`, `cart` → `cart_page_view`, `other` → `other_page_view`); event-API parameters get Insider's names (`pid` → `product_id`, `na` → `product_name`, `up`/`usp` → `unit_price`/`unit_sale_price`, `c_*` → custom parameters; `nc_*` copies are dropped). AppOTA_Insider sheets (R1511) describe events in this `{event, default_parameters, custom_parameters}` form, so web Insider hits are checked against them in it, without the app-only fields (`app_version`, `device_*`, `os_version`, `platform`).
- A hit's page is the page the hit names (`page_location`/`dl` for GA4, `current_url` for Insider), not the tab URL at the time the request left, so hits sent after an SPA navigation keep their own page.
- A business hit with the same vendor, GA4 measurement ID, event name and page (host + path) as the previous one within 10 s is a repeat: the activity row carries `repeat` and firing checks add a DUPLICATE warning. A site sending each event to two GA4 properties is not repeating.
- Not events: the Google Signals copy of each GA4 hit to `stats.g.doubleclick.net/g/collect` (no event name), Insider's `user` profile-sync hit, and Insider SDK signals sent through `dispatch` (anything that is not a snake_case event name, e.g. `userLocationSet`, `web-sdk:log`).
- HTTP success proves a network response, not vendor ingestion. First-party or unfamiliar vendors require explicit endpoint patterns and a supported decoder/rules. Opaque fields must remain unparsed evidence rather than inferred business events.

Limitations: very early events in a newly opened tab before the next discovery poll can only be recovered from its queue backlog; start the test step after that tab is attached. Worker-only requests and already-finished requests before attach may not be available. Nonconfigurable/frozen custom queues cannot be safely wrapped. Existing vendor accessors retain their own semantics and use the polling fallback.

## Verification

`node --test tests/cdp-injection.test.mjs tests/cdp-connection.test.mjs tests/cdp-browser-close.test.mjs` runs isolated queue, launcher and mock-CDP tests. It includes nested vendor wrappers, late/replacement queues, stop/restart, missing request body retrieval, interleaved CDP responses, lifecycle separation, bounded cleanup of stalled frames/callbacks, startup cancellation, and owned-browser identity checks.

Optional real-browser read-only Trip.com smoke in PowerShell:

```powershell
$env:EVENTQA_LIVE_CDP = '1'
node --test tests/cdp-live.test.mjs
Remove-Item Env:EVENTQA_LIVE_CDP
```

It uses a dedicated headless Chrome profile and saves observations under `runs/live-trip-cdp/`. It navigates to the homepage only, makes no synthetic analytics calls and does not claim tracking PASS/FAIL without a Trip specification. Its additional Trip telemetry hostname was observed in browser network requests. The live test is skipped by the normal test suite. A managed execution sandbox may block browser WebSocket frames even when `/json/list` works; the interactive product itself does not require a sandbox exemption.

Protocol reference: https://chromedevtools.github.io/devtools-protocol/ (Runtime, Page, Network, Target domains).
